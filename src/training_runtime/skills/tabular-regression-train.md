# 「剩余时长」表格回归训练方法

把一段设备历史时序做成「从当前时刻起，还需多久到达目标状态」的回归模型。

**这是一份示例领域 Skill，用来演示两层 Skill 架构的第二层能写什么。** 场景、字段名、阈值都可以替换；
真正值得复用的是下面五类内容：**数据准入门槛、时点正确性口径、特征白名单纪律、训练与评估协议、交付产物契约**。

典型任务形态：设备在 `T_cutoff` 之前的读数已知，要回答「几点启动才能在 `T_target` 达到目标状态」。
`T_cutoff` 之后的任何数据**一律不能进入特征**——这是本方法最核心的约束。

---

## 1. 数据准入清单

### 1.1 必需的三样（缺任何一样做不出效果）

| # | 数据 | 最低要求 | 缺了会怎样 |
|---|---|---|---|
| **A** | **状态时序**（决定标签的那个测点） | 原始上报 ≤1min，连续 **≥12 个月**，有效覆盖率 **≥75%** | 没有替代品，这是唯一的信号输入 |
| **B** | **历史事件时刻真值**（每次「启动」的实际时刻） | 覆盖 A 的 **≥80%** 天数，精度 ±5min，且**必须是该设备专属** | 没有它就没有标签，样本进不了训练 |
| **C** | **目标状态判据**（如目标温度/压力的实测口径值） | 该测点在稳态期的**实测值**，逐日 | 用名义设定值会引入系统偏置 |

**A 的补充**：允许长缺口，但缺口**不能插值补**（见 §3.2）。`cutoff` 前 48h 覆盖率不足的天，误差会明显偏高。

**B 的三种来源，按可靠性排序**：
1. 与启动强相关的另一路通道的上升沿检测（连续上升 ≥10min、斜率超过阈值）—— 最可靠，但**必须校正到统一口径**
2. 系统导出的运行区间日志
3. 排产/计划表 —— **不可用**，见 §2.4

**C 的取法**：从同一测点的稳态段反推（超过阈值的读数按日取中位，再做 31 天**居中**滚动中位）。
居中窗口在这里是**正确的**，不要"改成因果版"：目标状态是计划下发的阶跃量，`cutoff` 时已精确已知，
离线反推只是在复原一个已知量。

### 1.2 明确**不需要**的（别为它们等数据）

室外气温、能耗流量、产量计数器、控制器设定值通道 —— 在参考实现里这几类特征的贡献均为零。
三条替代补偿已经够：

- 季节谐波 `doy_sin / doy_cos`
- 从衰减段反推的「设备感受到的环境基线」（比气象站数据更贴近设备实际）
- 用「当前值 − 环境基线」归一化的变化率

**这条是迁移时最大的减负项**：新设备只要有状态时序 + 事件时刻就能开工。

### 1.3 样本量门槛

| 样本量（有事件真值的天数） | 判断 |
|---|---|
| < 80 | **不出模型**（`MIN_TRAIN=80` 是硬闸）。确有完整周期时可按 §1.4 降级 |
| 80 ~ 200 | 只能做单模型 + 留出评测，别信滚动数字 |
| 200 ~ 400 | 可用，但极端工况档基本学不动 |
| ≥ 500 | 能稳定复现分档指标 |

**同型两台设备合并训练 + 加设备标记特征**通常优于单台。
但**统计噪声下限时切忌合并**（残差分布不同，合并会把设备间差异算成噪声）。

### 1.4 短数据降级流程（**仅技术验证，产出不可用于生产决策**）

数据天数不足或不连续，但确实含完整状态周期时，按本节降级出模型。
不满足下面任一前置条件，**维持 §1.3 的「不出模型」，不要降级** ——
用没有状态变化过程的数据训出来的模型会照常部署成端点、照常返回数字，比直接失败危险得多。

**前置硬条件（三条缺一不可）**

| 条件 | 判据 |
|---|---|
| 确实存在完整状态周期 | 该测点最大值达到目标状态附近；若全程只在基线附近波动，说明取错了测点，**到此为止** |
| 有事件真值的天数 ≥ 30 | 管线应直接打印这个数 |
| 至少一段连续 ≥14 天 | 供「最近表现」与「停机时长」特征使用 |

**允许覆盖的参数（只有这三个）**：`MIN_TRAIN` 80 → 30 ｜ 分档标定最小样本 12 → 6 ｜ 训练脚本跳过滚动评估

**明确不允许动的两个**：结构性过滤的「当前值与目标值差距下限」和「到达耗时上限」——
它们剔掉的是**本来就不该建模的天**（当天没有过程可预测 / 停产异常）。放宽不是多拿样本，而是掺噪声。

**不连续本身不需要额外处理**：短缺口插值、长缺口留 NaN 是正确行为；断档处的天会被
「cutoff 前 60min 网格 + 末格非 NaN」条件自动剔除。

**必须补的评测**：末尾 **20% 连续区块**留出，不要随机抽行（相邻天高度相关，随机抽等于把答案漏给训练集）。

**必须写入 `evaluation_report.json` 的降级标记**：

```json
"model_status": "degraded_insufficient_data",
"usable_for_production": false,
"degradation": {"min_train_used": 30, "eval_method": "holdout_last_20pct",
                "rolling_origin": "skipped"}
```

## 2. 开工前的四项可行性检验

任何一项不过，先解决数据问题，别开始建模。

### 2.1 每天是否只有一次「停机 → 变化 → 稳态」循环

整个标签口径建立在「一天一次」上。先画 30 天曲线目视确认。
若一天多次（换型、双班），标签定义要重做，本方法不能直接套。

### 2.2 `gap`（目标值 − cutoff 当前值）的分布够不够宽，且候选区间有覆盖

低 `gap` 段是重灾区：样本稀少，而该段往往存在一个耗时地板。
树模型在没见过的区间不外推，所以必须配一条会外推的直线（§5 修法二）。
若新设备的 `gap` 分布集中在一个窄带里，直线标定会失稳，先看 §9 的护栏。

### 2.3 不可约噪声下限估计（配对法）——**只用来定期望，不要当靶子**

同设备同工况配对，取 `|Δ耗时|` 中位。**估计对配对判据极度敏感**：
配得越松 → 混进真实可解释差异 → 下限被**高估**；配得越紧 → 剩下的天在未观测维度上也更相似 → 下限被**低估**。
所以只能给区间。**配对判据里必须含「停机时长」**，漏掉它会让下限虚高，容易误判成泄漏。

### 2.4 事件时刻记录的质量核验（**最容易翻车的一项**）

三道检查，全过才能用：

**(a) 曲线锚点交叉校验** —— 状态曲线的局部极值才是真实事件时刻。
若记录系统性偏离曲线锚点，标签会偏短、变化率虚高。**判据：记录偏离锚点 >10min 判为不可信。**

**(b) 物理闸** —— 事件时刻的读数不能违反物理方向（如停机中只会衰减），给小容差。
上线这道闸通常是全部改动里单项收益最大的一步。注意闸太松也不行。

**(c) 专属性检查（必查）** —— 拿到事件区间日志后**第一件事是跨设备 diff**。
如果多台不同型号、不同厂区的设备共享**完全相同**的逐秒事件清单，那不可能是真的
（两台设备不会在同一秒启动），说明导出环节把同一份清单复制到了每个设备目录下。
相同即视为来源不明，退回用该设备自己的通道检测；两者都没有 → 这台设备不可训练。

## 3. 数据管线

产出两个文件，喂给特征构建步骤：

```
series_1min.parquet   index=1min 时间戳, columns=各设备状态值
cases.csv             一行 = 一次「cutoff 预测」
                      case_id, entity_id, day, cutoff, target_value, v0,
                      t_reach, reach_min, t_event, lead_min, dow, cov24h, cov48h
```

管线这一步**不要自己重写**——它有四个**静默失准点**，错了不报错，只是标签整体偏移：

1. **秒不截断到整分**。现场时间戳的秒往往集中在某个偏移上。不 floor 的话，后面所有
   「按位置回看 k 行 = 回看 k 分钟」的特征全部错位。
2. **同分钟聚合口径错**。按通道分：单调型取 `max`、外生量取 `mean`、状态量取 `last`。
3. **插值用双向而不是单向**。缺口横跨 `cutoff` 时，双向插值会把 `cutoff` **之后**的值插进当前值，
   而在已插值的产物上做任何泄漏测试都发现不了。
4. **不重建 1 分钟网格**，只用非空点。回看是按位置的，网格不齐则「往前 k 行」≠「往前 k 分钟」。

### 3.1 多源并集，不做单位/口径转换

新数据优先、老数据补空（同一测点先验证相关性）。原始数据常有**重复时间戳**，去重后再聚合。

### 3.2 缺口：≤15min 插值，更长**整段留 NaN**

状态时序决定标签，长缺口插值 = 编造观测。**并且插值必须是单向的**（见上第 3 点）。

### 3.3 平滑：标签侧可居中，特征侧**必须只回看**

- 标签判定用 `center=True` —— 允许，标签是事后定义的真值
- 特征计算用因果平滑（不带 center）—— 否则平滑窗口自己就跨过了 `cutoff`

### 3.4 到达时刻：首次 `value ≥ target − tol`

从 `cutoff` 往后找限定窗口内第一次命中。因为逼近段变化率较高，
目标值的小扰动只让 `reach_min` 移动约一分钟 —— 标签↔特征的循环耦合被限制在零点几分钟。

### 3.5 事件时刻：取候选里**最靠前**且过物理闸的那个

取最靠后是错的：运行区间日志一天多段，到达前往往还有第二、三段，
取最后一个会把事件时刻挪到设备已经接近目标之后，产生「事件时刻的读数比 cutoff 还高很多」这种
物理上不可能的标签。

⚠️ 候选筛选里的「事件时刻 ≤ 到达时刻」用到了标签，物理闸也读了 `cutoff` 之后的平滑值。
在当前数据上可验证结果不变，但**换一个更嘈杂的事件源时这就是陷阱**，必须重新验证。

### 3.6 结构性过滤 vs 按结果过滤

只允许按 `cutoff` 时可知的量过滤：
- 当前值与目标值的差距下限（否则当天没有过程可预测）
- `cutoff` 前 20min 内至少若干个真实数据点（否则 `asof` 会取很久以前的值）

「到达耗时超过上限则剔除」**是按结果过滤**，`cutoff` 时无法知道，会使报出的指标偏乐观。
迁移时三选一并**如实披露**：(a) 保持并披露；(b) 改成只按可知量筛；(c) 用 clip 而非丢弃。

## 4. 标签口径

**标签 = 「事件时刻 → 到达时刻」的分钟数，不是「cutoff → 到达」。**

事件时刻已知时两者只差一个常数，但前者噪声低得多：
「cutoff 到事件之间什么都没发生的等待时间」长短取决于排产，与设备物理无关，算进标签纯属掺噪声。
而且前者**与决策时刻无关**，这让反解和滚动决策都成立。

试过并**失败**的变体：分工况切换标签口径 → 变差。

## 5. 特征：约 120 维，全部由状态时序派生

六类：

| 类 | 内容 |
|---|---|
| 基础 | 当前值 / 目标值 / 差距 / 提前量 / 星期 / 季节谐波 / 覆盖率 |
| 变化率 | 多个窗口 × (原始 + 归一化) |
| 指数衰减拟合 | 多个拟合窗口 → 环境基线 / 时间常数 / 拟合质量 |
| 蓄能 | 多个指数权重时常数 + 积分量 |
| 衰减曲线形状 | 对数间隔采样点 |
| 历史 | 真实停机时长（长回看）/ 最近若干条已完成过程的表现 |

### 三条修法（缺任一都会明显掉点）

**修法一：差距按「事件时刻」算，不按「cutoff」算 —— 最关键的一步。**
过程从事件时刻才开始。若事件时刻晚于 cutoff 很久，设备在这段时间里还在继续衰减，
按 cutoff 算的差距会小一截，把样本推进训练数据几乎空白的区域。
用指数衰减模型外推到事件时刻，参数**只用 cutoff 前的衰减段标定**。

外推必须**自适应**（判据是最近实测变化率）：变化率很小时放弃外推（曲线已平，外推只放大噪声）、
足够大时完全信任、中间线性混合，再加「模型外推 vs 线性外推差异过大时取保守侧」的交叉校验。
**全局无条件外推反而不如不外推。**

⚠️ **混合阈值必须在最终指标上定，不能在中间量上定**：
把阈值调到让「事件时刻的读数」最准，下游最终指标反而会变差。
因为中间量是**特征**不是答案，模型要的是「对区分不同天有用」，不是「绝对值最准」。

**修法二：给树配一条会外推的直线。**
两参数线 `耗时 = A + B × 差距`（简单到不可能过拟合，天生会外推），把它的预测当**一维特征**喂树
（stacking），不单独出预测。护栏：斜率与截距各限定物理范围；该档样本过少时退回上一级标定。
⚠️ **标定这条线时必须剔异常值**，因为直线只有两个参数，一个离群点就能把斜率拽歪 ——
但**同一条清洗规则对树模型是有害的**（见 §6）。

**修法三：停机时长必须单独长回看。**
基础特征的回看上限会把一批样本（多为长假后首日）全压成同一个值，
而组内「真实停机时长 vs 标签」的相关性很高 —— 模型对最难那批天最关键的变量瞎了。单独开长回看窗口。

### 特征列必须用**正向白名单**

`F = [c for c in df.columns if c not in META]` 这种反向写法在参考实现里犯过**三次**同类事故，
每次都不报错不警告：

1. merge 外部看板数据 → 一个与标签高度相关的列进了特征
2. 实验脚本加诊断列 → 成了多出来的一个特征，污染一批对比数字
3. 校验脚本加「已校正标签」列（本质是标签）→ 基线指标假性下降

改成正向白名单（显式列表 ∩ df.columns）+ 重训时断言特征集合与交付模型完全相等。
注意别把合法特征一起挡掉 —— 误挡一个关键特征会让指标崩坏数倍。

## 6. 训练协议

```
三族模型取中位数：XGBoost + ExtraTrees + GBM_huber
滑动训练窗口 365 天 · 滚动评估每 7 天重训 · 预测值物理裁剪
```

**为什么取中位而不挑最好的**：横向比过多种模型 × 多种目标变换，前几名只差噪声级的量，
挑第一名是在噪声上做选择。取三个**不同算法族**的中位数：错法不同能互相抵消，中位数还抗离群。
副产品：三者极差可当置信度标注（**只覆盖一部分大误差，有确认的漏报**，不是安全网）。

**为什么 365 天**：工况会漂移，一年窗口既跟得上漂移又保住样本量。

**训练集故意不做异常值剔除**，只做 §3.6 的结构性过滤。测过多种剔除规则**全部无收益或有害**：
样本量本就不大**丢不起**，而被剔掉的往往正是稀有工况的信息。
树有上百维特征，离群点只影响局部叶子；直线只有 2 个参数，必须清（§5 修法二）。
**同一条清洗规则，对线性模型必需，对树模型有害。**

## 7. 评估协议

两套并用，回答不同问题：

- **滚动原点**：预测第 N 天只用之前的数据训练，每 7 天重训 → 「系统一直在线、定期重训」
- **单模型 + 分层留出**：每季留一个 **21 天连续区块** + 最后一段作最终测试 → 「训一个模型部署下去」
  **必须用连续区块而非随机抽行** —— 相邻天高度相关，随机抽行等于把答案漏给训练集

两者基本一致则说明不需要频繁重训。

### 四条报数纪律

1. **禁止 `trunc()` / 取整**。`|trunc(x)| ≤ |x|` 恒成立，而对手的数字若本来就是整数则不受影响 ——
   这一步会单向送掉零点几个单位。
2. **不能只报总平均**，必须分档：常规日 / 极端工况 / 长假后首日 / 已在过程中 / 最近 6 个月 / 分设备。
   常规日与极端工况档可能差近 2 倍。
3. **评估路径必须复用部署路径**。自己重写一遍训练循环会让窗口起点算法差几天，同一份数据跑出飘动的结果。
4. **区分「过程耗时误差」和「到达时刻误差」**。前者与线上同口径、公平；
   后者要求事件时刻本身准，数值会差很多。**不要用前者的数字去承诺后者。**

### 防泄漏必测三项

- **逐特征截断测试**：把 `cutoff` 之后的值换成 (a) 真实数据 (b) 交替毒值 (c) NaN，
  每个特征值必须**完全不变**。平滑要在截断后的序列上做，复现真实调用路径。
- **落盘产物本身重算**：从原始数据重算足够多例，与交付的特征矩阵逐列比对（验证矩阵，不只是函数）。
- **最近表现的因果性**：往 history 里塞当天 + 未来的毒记录，结果必须不变。

⚠️ 截断测试对**标量输入**结构性失明（标量参数是直接传进去的，测试只截断时序）。
凡是标量参数，可得性要单独论证。

## 8. 验收门槛

新设备达到以下全部才算「复现了参考效果」：

| 项 | 门槛 |
|---|---|
| 常规日 MAE | 低于目标阈值，且「≤2 倍阈值」占比 **> 90%** |
| 推荐事件时刻 MAE | 应比过程耗时 MAE **更小**（存在耦合；若没有这个关系说明耦合项算错了） |
| 迟到风险 | 样本外窗口内**迟到超过容差的天数 = 0** |
| 相对不可约下限 | MAE 在下限的 1.2~1.5 倍内；**低于下限 → 查泄漏** |
| 相对基线 | 明显优于线上算法/朴素外推基线，且**误差方向偏安全侧** |
| 泄漏测试 | §7 三项全过 |

**这套方法最大的价值不是平均更准，而是不会危险地迟到。** 验收时把这条放在 MAE 前面。

## 9. 换设备时：必须重标的 vs 可直接沿用的

| 常量 | 迁移动作 |
|---|---|
| `CUTOFF_HOUR` / 目标时刻 | **现场给定**，问清楚 |
| 目标状态口径 | **必须重新确认**（换测点或做过校准后同样要重确认） |
| 差距下限 / 耗时上限 | 按该设备的分布重定 |
| 事件源口径校正量 | **必须重测**（两来源重叠区比中位差） |
| 外推混合阈值 | **在该设备的最终指标上重扫**，不要沿用 |
| 两参数线 `(A,B)` | 每次 fit 自动标定，但要检查是否撞护栏 |
| 直线标定的清洗带 | 按该设备的变化率分布重定 |
| 窗口天数 / 重训周期 / `MIN_TRAIN` | 可沿用 |
| 特征定义、三族模型、评估协议、正向白名单 | **可直接沿用**，这部分与设备型号无关 |

## 10. 已知无效路径（别再走）

| 尝试 | 结果 |
|---|---|
| 分工况切换标签口径 | 变差 |
| L1/huber 损失全替换 | 变差 |
| 极端工况档单独标定骨架 + 样本加权 | 变差，且难组偏置纹丝不动 |
| 多决策时刻混合训练（数据成倍增加） | **主决策时刻精度被稀释** |
| 把外推阈值调到中间量最准 | 中间量变准，下游变差 |
| 训练集剔异常值（多种规则） | 全部无收益或有害 |
| 主时刻模型直接拿到更早的时刻用 | 精度崩坏（应单独训早轮专用模型） |

**早轮怎么办**：早轮的任务不是给精确时刻，而是回答「今天要不要提前动作」这个二元问题
（不同工况之间的差距远大于模型误差，粗判也分得开）。
一个主时刻模型 + 早轮只做粗判；等那部分精度要紧了再单独加模型。

## 11. 上线口径

1. **目标状态传测点口径实测值**，不是计划名义值。
2. **事件时刻是输出不是输入**：用二分反解 `t + 耗时(t) = 目标时刻`（该函数单调递增）。
   内核「给定事件时刻算耗时」是条件预测，不要当主接口。
3. **每 15min 跑一轮**：反解出推荐时刻，若它早于「本轮时刻 + 15min」就必须现在提交，
   否则等下一轮（数据更新、外推更短、更准）。
4. **极端工况报区间**，不报单点。
5. **强制重建 1 分钟网格**（缺的分钟留 NaN 不插值）。否则现场传低分辨率 / `dropna()` 过的 /
   乱序带重复时间戳的数据时，回看特征会**静默错好几倍**。
6. **安全裕度**：反解时可要求「提前 N 分钟到达」而不是刚好卡点。裕度取该设备 MAE 的 1~1.5 倍；
   极端工况档单独放宽。这是「省资源」和「不延误」之间的旋钮。
7. **监控外推器**：把外推估计值与次日可得的真实值比，持续偏差过大说明标定漂了。
8. **冻结交付模型的特征名单**，重训时断言集合相等。

### 11.1 交付产物契约（**不满足则任务判失败或无法上线**）

所有产出必须写到提示词里 `Write all attempt outputs under:` 给出的**那个绝对路径**
（形如 `.../attempts/attempt-N/output`）。开头把它原样存成 `OUT` 变量，全程只用 `$OUT/`，
结束前 `ls -la "$OUT"` 确认。**不要自己拼路径，不要写到 workspace 根下的同名 `output/`。**

`$OUT` 里必须齐备这五项，缺任一即失败：

```
prediction.csv          预测结果，核验门禁的硬要求（缺它判不通过，与模型好坏无关）
evaluation_report.json  含 metric_name / metric_value / 分档结果
model.joblib            模型权重
inference.py            推理入口，见下
<算法包目录>/           inference.py 要 import 的包，整个目录一起拷
```

`inference.py` 的契约（SageMaker 框架容器约定的子集）：

```python
def model_fn(model_dir):
    """必需。返回加载好的模型对象；返回 None 视为失败。
    model_dir 会被加入 sys.path，所以包内 import 可直接用。"""

def predict_fn(data, model):
    """建议实现。data 是 instances 列表（每项一个 dict）。
    缺省行为是 model.predict(DataFrame(instances))；自定义模型通常不符合这个接口。
    返回 list —— dict 原样透传；标量会被包成 {"prediction": 值}。"""
```

若权重是「纯字典 + 由类方法还原」的形式，**少了算法包，权重文件本身没有意义** —— 必须一起交付。

交付前自检：

```bash
ls -la "$OUT"
python3 -c "
import sys; sys.path.insert(0,'$OUT')
import inference; m=inference.model_fn('$OUT')
assert m is not None; print(type(m).__name__)"
```
